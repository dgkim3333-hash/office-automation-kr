# office-automation-kr 설계문서

작성일 2026-10-28 · 상태: 설계 승인, 구현계획 대기

## 1. 목적

해외 본사 제품을 국내 고객에게 판매하는 지사의 오더 담당자(이하 "사용자") 한 사람이, GitHub 문서만 읽고
① Claude Desktop(Code 탭)과 Python을 설치하고 ② 고객 PO·Invoice·DM PDF를 폴더에 넣으면
엑셀 장부에 행이 자동으로 쌓이고 파일이 정리되는 상태를 혼자 만들 수 있게 한다.

성공 기준
- 설명자 개입 없이 문서만으로 설치~첫 실행 완료.
- 가짜 샘플 PDF 6종(Invoice 2 · DM 2 · 서신 1 · 스캔 1)으로 10분 안에 "엑셀 행이 생기는" 체험.
- 사용자가 자기 양식을 Claude Code로 가르친 뒤, 매일 처리는 Claude 없이 돈다.
- 매일 처리(run.bat)에서 회사 문서 내용이 PC 밖으로 나가는 경로가 0개. Claude 에게는 사용자가 보여 준 가린 샘플만 간다.

## 2. 전제와 제약

| 항목 | 결정 |
|---|---|
| 데이터 경계 | 회사 문서는 Anthropic 서버·Gmail 등 외부로 전송하지 않는다. Claude는 코드·규칙을 만드는 도구로만 쓴다. 프로그램은 내 PC 에서만 실행한다: Windows 가 아니거나 클라우드 실행 환경이면 멈추고, 실행 중 인터넷 연결을 코드로 막는다(`local_guard.py`, 2026-10-28 추가). 작업 폴더는 로컬 디스크만. |
| 샘플 | 저장소 제작 시 실제 양식 샘플 없음. 사용자가 자기 PC에서 가린 샘플을 Claude Code에 보여 주며 규칙을 만든다. |
| 1차 범위 | PDF(Invoice·DM) → 엑셀 누적 + 파일 정리. ERP 입력·메일 발송·OCR(스캔본)은 범위 밖. 고객 PO 가 엑셀로 오는 흐름(고객 엑셀 → 회사 SO 양식)은 2차로 미룬다(2026-10-28 결정, 09장 자리만). |
| 메일 수집 | 기본은 사용자가 첨부를 직접 폴더에 저장. 선택: Outlook 데스크톱 앱이 있으면 pywin32로 로컬 복사(08장). |
| 환경 | Windows 전용. Claude Pro 이상. 설치 권한 있음. |
| 저장소 | 새 공개 저장소(기존 claude-guide-kr과 분리). 회사 정보 일체 없음. 사용자의 실제 `규칙.yaml`은 저장소 밖 작업 폴더에만 둔다. 사용자는 ZIP 또는 clone만 하고 push하지 않는다. |
| 독자 | GPT 사용 경험 있음, Claude·Claude Desktop 처음, 비개발자. |

## 3. 전체 흐름

```
회사 메일 ─(사용자 저장 / 선택: Outlook 로컬 복사)─▶ 받은문서/
                                                    │ run.bat 더블클릭
                                                    ▼
    app/  PDF 텍스트 추출 → 문서종류 판별(PO·Invoice·DM)
          → 작업 폴더의 규칙.yaml 로 필드·표 추출
          → 누적장부.xlsx 행 추가 (중복 방지)
          → 정리문서/고객명/YYYY-MM/문서종류_번호.pdf 이동
          → 처리로그.csv 기록 · 실패 건은 확인필요/
```
Claude Code는 `규칙.yaml`을 만들고 고칠 때만 등장한다.

사용자 PC의 작업 폴더(저장소 밖, 로컬 디스크, 예: `C:\사무자동화\`):
```
사무자동화/
  받은문서/   받은문서/중복/   정리문서/   확인필요/
  누적장부.xlsx   처리로그.csv   규칙.yaml  ← 사용자 실제 규칙. 02장에서 규칙.예시.yaml 을 복사해 시작
```
작업 폴더 위치는 저장소 루트의 `작업폴더.txt`(경로 한 줄)로 지정하며 `설치.bat`가 만든다. 저장소와 작업 폴더를 분리해 ZIP을 새로 받아도 데이터가 안 섞인다.

### 4-1. 설치.bat — 작업 폴더 선택 (`python -m app init`)

1. Windows 폴더 선택 창(tkinter `askdirectory`, 추가 설치 없음)을 띄운다. 취소하면 콘솔에서 "경로를 직접 입력하세요"로 대체.
2. 선택한 폴더에 `받은문서/ 받은문서/중복/ 정리문서/ 확인필요/`를 만들고, `rules/규칙.예시.yaml`을 `규칙.yaml`로 복사한다(이미 있으면 건드리지 않음).
3. 저장소 루트 `작업폴더.txt`에 경로를 저장한다(.gitignore).
4. 끝에 "작업 폴더: <경로>" 와 "이제 04장으로 가세요." 를 출력한다.
- 재실행 시 현재 경로를 보여 주고 "바꾸시겠습니까?"만 묻는다. 기존 데이터는 이동하지 않고, 새 경로에 빈 구조만 만든다.
- 저장소 폴더 자체(또는 그 하위)를 고르면 거부한다 — ZIP을 새로 받을 때 데이터가 날아갈 수 있다.
- 동기화 폴더(OneDrive·Dropbox 등)·네트워크 드라이브·UNC 경로는 거부한다. 장부·PDF 가 PC 밖으로 복사되기 때문(2026-10-28 결정, 이전 「OneDrive 허용」 대체). 02장은 `C:\사무자동화` 를 권한다.
- `run.bat`는 `작업폴더.txt`가 없거나 경로가 사라졌으면 "설치.bat를 먼저 실행하세요"만 출력하고 멈춘다.

## 5. 규칙.yaml 구조

```yaml
문서종류:
  DM:                                           # 검사 순서가 의미를 가진다 — 아래 '결정' 참고
    판별키워드: ["DEBIT MEMO", "Debit Memo No"]  # 1쪽 텍스트에 하나라도 있으면 이 종류
    번호필드: DM번호                             # 중복 키 · 파일명에 사용. 필수
    필드: …Invoice 와 같은 구조…
  Invoice:
    판별키워드: ["Invoice No"]                   # "INVOICE" 는 DM 의 "Reference Invoice" 에도 걸려서 좁힘
    번호필드: 인보이스번호
    필드:
      인보이스번호: {패턴: "Invoice No[.:]?\\s*([A-Z0-9-]+)"}
      발행일:      {패턴: "Date[.:]?\\s*(\\d{1,2}/\\d{1,2}/\\d{4})", 형식: 날짜}
      고객명:      {패턴: "Bill To:[^\\n]*\\n(.+?(?:Co\\., Ltd\\.|Inc\\.))"}
      합계금액:    {패턴: "\\nTotal[.:]?\\s*\\$?([\\d,]+\\.\\d{2})", 형식: 금액}
    표:                                         # 선택
      시작키워드: "Line Item Description"
      끝키워드: "Subtotal"
      행패턴: "^(\\d+)\\s+(\\S+)\\s+(.+?)\\s+(\\d+)\\s+([\\d,]+\\.\\d{2})\\s+([\\d,]+\\.\\d{2})$"
      열: [줄, 품번, 품명, 수량, 단가, 금액]       # 행패턴의 괄호 순서 = 열 순서
      금액열: [단가, 금액]                        # 선택. 엑셀 숫자(달러)
      수량열: [수량]                              # 선택. 엑셀 정수
    파일명: "{고객명}/{발행일:%Y-%m}/Invoice_{인보이스번호}.pdf"
  PO:  …같은 구조… (1차에서는 자리만. 고객 PO 가 엑셀로 오는 흐름은 2차 — 09장)
```
결정
- 추출은 정규식만. 좌표 기반 추출은 쓰지 않는다 (양식 변화에 약하고, Claude Code가 가장 잘 만드는 것도 정규식).
- 표는 **행패턴 한 방식만**: 시작~끝 키워드 사이의 빈 줄이 아닌 각 줄에 `행패턴`을 맞추고, 괄호 순서대로 `열`에 넣는다. 품명에 띄어쓰기가 많아 "열 개수로 쪼개기"로는 안 되기 때문이다(2026-10-28 샘플 검증으로 변경). 한 줄이라도 안 맞으면 품목만 건너뛰고 경고. 행패턴의 괄호 수와 열 수가 다르면 규칙 오류.
- 형식 변환은 필드의 `날짜`(엑셀 날짜형) · `금액`(달러 숫자 그대로, 엑셀 숫자형), 표의 `금액열`(숫자) · `수량열`(정수)뿐. 원화 풀 콤마 규칙은 적용 대상 아님(해외 본사 달러 문서).
- 문서종류는 **적힌 순서대로** 검사하고 먼저 맞는 종류로 정한다. 순서가 결과를 바꾼다: DM 본문에 "Reference Invoice" 가 있으므로 DM 을 Invoice 보다 먼저 두고, Invoice 판별키워드는 "INVOICE" 대신 "Invoice No" 로 좁힌다. 05장에 이 사례를 싣는다.
- `rules.py`가 시작 전 구조를 검증한다: 정규식 컴파일, 번호필드가 필드에 존재, 파일명 템플릿의 변수가 필드에 존재, 행패턴 괄호 수 = 열 수, 금액열·수량열이 열에 존재.

레시피 프롬프트(05장) 골자: "이 샘플 PDF를 읽고 위 구조의 Invoice 항목을 만들어 작업 폴더의 `규칙.yaml`에 넣은 뒤 `uv run python -m app check <샘플>` 결과를 보여 줘." 사용자는 표를 보고 "고객명이 비었어" 식으로 고치게 한다.

## 6. CLAUDE.md (Claude Code 행동 지침)

- `app/` 코드는 수정하지 않는다. 고칠 것은 작업 폴더의 `규칙.yaml`만. 저장소의 `rules/규칙.예시.yaml`도 건드리지 않는다.
- 결과는 반드시 `check` 명령 출력으로 보여 준다. 추측으로 "됐다"고 하지 않는다.
- 금액은 달러 숫자 그대로. 날짜는 `형식: 날짜`.
- 샘플 PDF 내용을 다른 파일·채팅 요약에 복사하지 않는다.
- 사용자가 코드 수정을 요구하면 "설계상 규칙 파일로 해결 가능한지" 먼저 확인하고, 불가하면 99장의 문의 경로를 안내.

## 7. 엑셀 누적 방식

파일 `누적장부.xlsx` 하나.

| 시트 | 한 행 | 열 |
|---|---|---|
| Invoice / PO / DM | 문서 1건 | 처리일시 · 원본파일 · 규칙.yaml 필드 순서 · 정리된경로 |
| 품목 | 품목 1줄 | 문서종류 · 문서번호 · 표의 열 순서 |
| 처리로그 | 처리 시도 1건 | 일시 · 파일 · 결과(성공/중복/확인필요) · 사유 |

결정
- 중복 키 = 문서종류 + 번호필드 값. 중복이면 행 추가 없이 로그에 "중복", PDF는 `받은문서/중복/`으로.
- `--덮어쓰기` 옵션: 기존 행(및 품목 행)을 삭제하고 새로 기록. 고객 수정본 대응.
- 열은 규칙.yaml에서 자동 생성. 새 필드는 오른쪽 끝에 추가, 기존 열 순서·이름은 바꾸거나 지우지 않음.
- 각 시트는 openpyxl 테이블(헤더 고정·필터). 날짜·금액 셀 서식 지정.
- 엑셀이 열려 있어(잠김) 저장 불가면 전체 중단, 파일 이동 없음. `_v2` 저장 안 함.
- 기존 수기 장부는 건드리지 않음. 04장에 "한 달 병행 후 전환" 권고.

## 8. 오류 처리 · 파일 정리

| 상황 | 처리 | 확인필요 .txt 내용 |
|---|---|---|
| 문서종류 판별 실패 | 확인필요/ | "판별 실패" + 1쪽 텍스트 앞 30줄 |
| 번호필드 미추출 | 확인필요/ | 실패한 패턴 이름 |
| 선택 필드 미추출 | 성공 처리, 셀 비움, 로그 경고 | — |
| 텍스트 0자(스캔본) | 확인필요/ | "텍스트 없음 — 스캔본, OCR 범위 밖" |
| 표 열 개수 불일치 | 문서 행 기록, 품목 건너뜀, 경고 | — |
| 중복 | 받은문서/중복/ 이동 | — |
| 엑셀 잠김 | 전체 중단 | — |

원칙
- 원본 삭제·덮어쓰기 없음, 이동만. 정리문서/에 같은 이름 있으면 `_2`, `_3`.
- 파일 단위 처리. 한 건 실패가 나머지를 막지 않음. 끝에 "성공 N · 중복 N · 확인필요 N" 요약.
- 순서: 전체 추출 → 장부 저장 1회 → 성공한 뒤에만 파일 이동. 장부 저장 실패 시 이동 없음.
- 재처리: 규칙을 고친 뒤 `확인필요/`의 PDF를 `받은문서/`로 옮기면 끝(.txt는 함께 삭제).
- 처리로그.csv는 엑셀 잠김과 무관하게 항상 기록.

## 11. 문서 작성 원칙 (01~99장 공통)

- 독자는 혼자 읽는다. 각 장은 "이 장을 끝내면 무엇이 보여야 정상인지"로 시작하고 끝에 「다음 →」.
- 명령은 한 번에 하나, 코드 블록 하나. 블록 위에 무엇을 하는지 · 실행 후 무엇이 보여야 하는지 한 줄.
- 스크린샷 대신 "화면에 이런 글자가 보이면" 식 텍스트 기준 (스크린샷은 버전마다 바뀜).
- Claude Code에 붙일 프롬프트는 복사 버튼이 생기는 코드 블록으로.
- 회사명·고객명·실제 양식 정보는 저장소 어디에도 쓰지 않는다.
- 사용자는 처음부터 끝까지 **Code 탭(Local)**에서 작업한다. README 첫 박스와 02장 첫 줄에 이유와 함께 적는다: 「run.bat 처리는 이 PC 안에서만 돌고 인터넷으로 아무것도 보내지 않는다. Claude 에게 보여 준 것만 Claude 에게 간다.」 「채팅 탭에 PDF 를 올리거나 Cowork 에 회사 PDF 를 맡기지 않는다(Cowork 는 Anthropic 서버에서 돈다).」 「Code 탭에서만 하면 정보가 밖으로 안 나간다」는 쓰지 않는다(2026-10-28 정정). Code 탭이 안 보이면 요금제(Pro 이상) 문제일 가능성이 가장 크다(99장 첫 줄).
