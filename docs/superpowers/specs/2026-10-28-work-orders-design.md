# 작업지시서 · 여러 작업 · 매일 자동 실행 · 이중 확인 설계

작성 2026-10-28. 기존 설계(`2026-10-28-office-automation-kr-design.md`)에 덧붙인다. 겹치면 이 문서가 이긴다.
표기: **[대표]** = 대표가 대화에서 정한 것, **[설계자 판단]** = 이 문서를 쓴 쪽이 정한 것(대표 확인 전).

## 1. 왜

친구(비개발자)는 매일 손으로 정리하는 일이 5가지쯤 있다 **[대표 예상]**. 지금 프로그램은 받은문서 폴더 하나 · 규칙 하나 · 장부 하나뿐이라 일마다 따로 돌릴 수 없고, 매번 `run.bat` 을 눌러야 한다.
목표: 기본 설치가 끝난 뒤 친구가 Code 탭 Claude 와 **질문에 답하는 대화**만으로 일(작업)을 하나씩 만들고, 만든 작업은 **Claude 없이** 매일 정해진 시각에 돌며, 급하면 바탕화면 아이콘 더블클릭으로 바로 돈다. Code 탭이 그 친구의 「프로젝트」처럼 쓰인다.

## 2. 목표 · 하지 않을 것 · 실패로 보는 것

목표
- 작업을 1개씩 만들고 「계속 만드실까요, 그만하실까요?」로 이어 간다 **[대표]**. 개수 제한 없음(5개 안팎 예상).
- 작업마다: 제목 · 입력 예시 파일(엑셀 또는 PDF) · 출력 방식 · 입력 폴더 · 출력 폴더 **[대표]**.
- 출력 방식은 셋 중 하나: 회사 양식만 · 누적장부만 · 둘 다 **[대표]**.
- 매일 오후 4시 첫 작업, 이후 작업은 20분 간격(16:00, 16:20, 16:40 …) **[대표]**.
- 바탕화면 「지금 실행 - 작업 이름」 바로가기로 즉시 실행 **[대표]**.
- 숫자·소수점 오류 방지 이중 확인이 기본으로 들어간다. 느려져도 된다 **[대표]**.
- 새 작업은 처음 10건을 친구가 승인한 뒤부터 자동 **[대표]**.

하지 않을 것
- 매일 실행에 Claude(예정됨·Cowork·채팅)를 쓰지 않는다. Windows 작업 스케줄러가 프로그램을 직접 돌린다 **[대표]**.
- 손으로 만든 예전 결과(정답지)를 요구하지 않는다(친구가 주기 어렵다) **[대표]**.
- 메일 발송·클라우드 저장 등 외부 전송 기능.

실패로 보는 것 (돌아가더라도)
- 숫자 한 자리, 소수점 한 자리라도 원본과 다른 값이 회사 양식이나 누적장부에 **조용히** 들어감.
- 매일 실행 중 회사 문서 내용이 PC 밖으로 나감.
- 친구가 이 문서·화면 없이 혼자 못 씀(설명이 길거나 명령어를 쳐야 함).

## 3. 데이터 경계 (보안)

| 단계 | Claude 에게 가는 것 |
|---|---|
| 작업 만들기 대화 | 제목, 폴더 경로, **입력 예시 원본 파일 1개의 내용 전체**, 출력 양식 파일(회사 양식이면 그 빈 양식) |
| 매일 실행 · 지금 실행 · 승인 | 없음. Claude 가 끼지 않고, 프로그램은 실행 중 인터넷 연결을 막는다(`local_guard`) |

- 입력 예시는 **가린 사본이 아니라 원본** 1개를 쓴다 **[대표]**(가린 사본은 모양이 달라져 오류가 날 수 있으므로). 문서(04장·01장)에 「작업을 만들 때마다 원본 1개의 내용이 Claude(Anthropic 서버)로 한 번 간다」를 그대로 적는다.
- 고객마스터·누적장부·출력 결과는 작업 만들기 때도 Claude 가 열지 않는다(기존 CLAUDE.md 8항 유지).
- 기존 CLAUDE.md 의 「샘플은 가린 사본만」 문구는 이 결정에 맞게 고친다.

## 4. 작업 만들기 (작업지시서)

시작: 기본 설치 + 프로그램 설치 뒤, Code 탭에서 친구가 짧은 한 줄을 넣으면 Claude 가 아래 순서로 묻는다. 시작 방법(슬래시 명령 `.claude/commands/` 또는 붙여 넣는 한 줄)은 설계자 판단에 맡기되 **친구가 치는 글자는 한 줄 이하**.

질문 순서 (작업 하나)
1. 「무엇을 만들어 드릴까요? 제목을 입력해 주세요.」 (예: 일일 PO 정리)
2. 「입력할 파일(엑셀 또는 PDF)의 예를 하나 넣어 주세요.」 — 친구가 파일을 끌어다 놓거나 경로를 준다.
3. 「출력은 회사 양식, 누적장부, 둘 다 중 무엇으로 할까요?」 — 회사 양식이면 회사 양식 파일(빈 양식 또는 예전에 쓴 것)도 받는다.
4. 「입력 폴더를 고르세요.」 → 폴더 고르기 창(프로그램이 띄움, 기존 `init` 의 tkinter 방식).
5. 「출력 폴더를 고르세요.」 → 같은 방식.
6. Claude 가 규칙을 만들고 `check` 로 예시 파일 결과 표를 보여 준다. 비고 칸이 비고 아래 5절 자동 확인을 통과할 때까지 Claude 가 규칙을 고친다.
7. 프로그램이 작업을 등록한다: 실행 시각 배정 · Windows 작업 등록 · 바탕화면 바로가기 2개(「지금 실행 - 이름」, 「승인 - 이름」).
8. 「다음 작업도 만드실까요, 그만하실까요?」

규칙 만들기는 기존 엔진(규칙.yaml 의 문서 종류 · 엑셀양식 · 회사양식)을 그대로 쓴다. Claude 는 `app\` 코드를 고치지 않는다(기존 원칙).

폴더 제약: 입력·출력 폴더 모두 이 PC 의 로컬 디스크만. OneDrive·Dropbox·네트워크 드라이브·UNC 는 거부(기존 `check_work_dir` 재사용) **[설계자 판단, 기존 원칙 연장]**.

## 5. 정확성 이중 확인

### 5-1. 매번 자동 (모든 문서, 승인 뒤에도)
아래 중 하나라도 어긋나면 그 문서는 결과·장부에 넣지 않고 그 작업의 `확인필요\` 로 보낸 뒤 이유(.txt)를 남긴다.

1. **원문 대조**: 결과에 들어가는 숫자·번호·날짜는 모두 원본에 있어야 한다. 표기 차이(`1,234.50` ↔ `1234.5`)는 같은 값으로 보고, 자리·소수점이 다르면 불일치. 엑셀 원본은 셀에 저장된 값으로 대조(부동소수 오차는 셀 표시 형식 자리 수 기준으로 판단 — 구체 방법은 설계자 판단).
2. **줄 검산**: 품목에 수량·단가·금액이 모두 있으면 수량 × 단가 = 금액.
3. **합계 검산**: 문서에 합계 금액이 있고 품목 금액이 있으면 품목 금액 합 = 합계.
4. **저장 후 재읽기**: 결과 엑셀·누적장부를 저장한 뒤 다시 열어 방금 쓴 값과 한 칸씩 대조.
5. **소수점 자리 수**: 결과 값의 소수 자리 수 = 원본 값의 소수 자리 수. 반올림·잘라내기 금지(이미 Decimal 사용).

검산 항목에 해당 값이 없으면(예: 단가 없음) 그 항목은 건너뛰고 「검산」 시트에 「해당 없음」으로 적는다 **[설계자 판단]**.

문서마다 검산 기록: 항목 · 원본 값 · 결과 값 · 일치 여부(둘 위치는 10절 3).

### 5-2. 새 작업은 처음 10건 승인 **[대표]**
- 원문 대조로 못 잡는 실수(원본의 **다른** 숫자를 짚음, 예: 단가 자리에 금액)를 사람 눈으로 잡는다.
- 작업의 승인 수가 10건 미만이면, 5-1 을 통과한 문서도 결과를 바로 내지 않고 `승인대기\` 에 둔다. 대조표(항목 · 원본 값 · 결과 값)를 같이 만든다.
- 친구가 대조표를 보고 바탕화면 「승인 - 이름」을 더블클릭하면 승인대기의 문서를 결과·장부로 넘기고 승인 수를 센다. 건 = 문서 1개.
- 틀린 게 있으면: 친구는 그 문서를 `확인필요\` 로 옮기고 Code 탭 Claude 에게 「○○ 작업 규칙 고쳐 줘」라고 말한다 **[설계자 판단]**.
- 규칙이 바뀌면 승인 수를 0으로 되돌린다 **[설계자 판단]**(고객이 양식을 바꾼 경우 포함). 승인 수는 양식 단위로 센다(10절 6).
- 10건 승인 뒤에는 5-1 통과 문서는 바로 결과·장부로.

## 6. 매일 실행 · 지금 실행

- Windows 작업 스케줄러에 작업마다 1개 등록. 매일, 시각 = 16:00 + 20분 × (작업 순번 − 1) **[대표]**.
- 놓친 실행은 PC 를 켜면 바로 실행(StartWhenAvailable) **[설계자 판단]**. PC 가 그 시각에 꺼져 있을 수 있으므로.
- 현재 사용자 권한으로 등록(관리자 권한 요구 없음), 로그인했을 때만 실행 **[설계자 판단]**.
- 바탕화면 「지금 실행 - 이름」 = 같은 작업을 즉시 실행. 「승인 - 이름」 = 5-2. 콘솔 창에 결과 요약을 보여 주고 키를 누르면 닫힌다.
- 자동 실행(오후 4시)은 아무도 안 보고 있으므로, 결과 요약을 작업 폴더의 로그에 남긴다. 확인필요·승인대기가 생겼을 때 친구가 알게 하는 방법(Windows 알림 등)은 설계자 판단, 단 PC 밖으로 보내는 방법은 금지.
- 같은 작업이 두 번 겹쳐 돌지 않게 막는다(자동 실행 중 지금 실행 등).
- **회사 정책으로 막힐 때** (대표 질문 반영, **[설계자 판단]**): 회사 IT 정책이 사용자의 예약 작업 만들기를 막을 수 있다. 등록 직후 실제로 등록됐는지 다시 조회해 확인한다. 막혔으면 다음 방법으로 넘어간다(설치 스크립트의 「방법이 막히면 다음 방법」과 같은 방식).
  1. Windows 작업 스케줄러
  2. 시작프로그램 폴더 바로가기: 로그인할 때 「오늘 정해진 시각이 지났는데 아직 안 돈 작업」을 돌린다. 오후 4시 정각 실행은 못 하고, 다음 로그인 때 돈다.
  3. 둘 다 막히면 자동 실행은 없다고 친구에게 그대로 알리고, 바탕화면 「지금 실행」만 쓴다.
  - 어느 방법이 쓰였는지 작업설정.yaml 에 남기고, 작업 만들기 마지막 화면에 한 줄로 보여 준다.
  - 프로그램 실행(uv·python) 자체를 회사가 막으면 이 도구 전체가 동작하지 않는다. 99장에 「IT 담당자에게 물어볼 문장」을 둔다.
- 작업 삭제·일시정지: Code 탭에서 「○○ 작업 지워 줘 / 멈춰 줘」 → 프로그램 명령이 스케줄 · 바로가기를 함께 정리 **[설계자 판단]**.

## 7. 폴더 구조 (작업 폴더 안)

```
C:\사무자동화\
  작업\
    01_일일PO정리\
      작업설정.yaml    제목 · 입력 폴더 · 출력 폴더 · 출력 방식 · 순번/시각 · 승인 수 · 규칙 지문
      규칙.yaml
      누적장부.xlsx    (출력 방식이 누적 포함일 때. 위치는 출력 폴더로 해도 됨 — 설계자 판단)
      처리로그.csv
      승인대기\   확인필요\   정리문서\
    02_DM정리\ …
  고객마스터.xlsx      (작업 공용)
```
입력 폴더는 친구가 고른 곳(예: 메일 첨부를 저장하는 폴더). 처리한 원본은 입력 폴더에 두지 않고 그 작업의 `정리문서\` 로 옮긴다(기존 방식).

## 8. 기존 기능과의 관계

- 지금의 단일 흐름(받은문서 · run.bat · 04장)은 없애고 「작업」으로 완전히 바꾼다 **[대표, 2026-10-28]**. 친구는 아직 쓰기 전이므로 옮길 데이터가 없다. 설치 스크립트 · 설치.bat/init · 작업폴더.txt 구조 · 기존 시험(e2e 등)도 작업 방식에 맞게 고치고, 설치 업데이트 때 없어진 파일(run.bat 등)은 기존 정리 방식으로 지운다 **[설계자 판단]**.
- 04장 = 작업 만들기, 05장 = 자세히(규칙 고치기), 06장 = 매일(바탕화면 · 승인 · 확인필요), 07장의 「예정됨」 설명 = 왜 Claude 예정됨이 아니라 Windows 작업인지.
- `check`, 규칙 엔진, 장부, 회사 양식 변환, local_guard 는 재사용.

## 9. 테스트에서 꼭 다룰 것

- 원문 대조: 자리 다른 숫자, 소수점 다른 숫자, 표기만 다른 같은 값, 엑셀 부동소수(0.1 류).
- 줄·합계 검산 불일치 → 확인필요, 결과·장부 무변화.
- 저장 후 재읽기 불일치 시 동작.
- 승인: 10건 미만 승인대기, 승인 후 결과 생성 · 승인 수 증가, 규칙 변경 시 0으로.
- 스케줄 등록 명령은 실제 등록 없이 검증(드라이런), 바로가기 생성도 임시 폴더로.
- 두 작업이 서로의 폴더·장부를 건드리지 않음.

## 10. 검토 뒤 정한 것 [설계자 판단, 대표가 읽으며 확인]

1. **입력 폴더는 여러 작업이 같이 써도 된다.** 메일 첨부 폴더 하나에 PO·DM 이 섞여 들어오기 쉽기 때문. 작업은 **자기 규칙으로 판별되는 파일만** 가져가고, 판별이 안 되는 파일은 입력 폴더에 그대로 둔다(다른 작업 몫일 수 있으므로). 판별은 됐는데 추출·검산이 실패한 파일만 그 작업의 `확인필요\` 로 옮긴다. 어느 작업도 가져가지 않은 채 하루 넘게 남은 파일은 「지금 실행」 요약과 로그에 「어느 작업에도 맞지 않는 파일 N개」로 알린다. 출력 폴더도 같이 써도 된다(파일 이름에 번호가 들어가 겹치지 않음, 겹치면 기존 `free_name`).
2. **입력이 PDF 든 엑셀이든 출력 방식 3가지를 모두 지원한다.** 대화에서 대표가 입력(엑셀 또는 PDF)과 출력(회사 양식 · 누적)을 따로 고르게 했기 때문. 지금 엔진은 회사 양식을 엑셀 PO 에서만 만들므로, PDF 추출 결과(필드 · 품목 표)에서도 회사양식 규칙으로 회사 양식을 만들게 넓힌다. 고객마스터 조회도 같은 방식.
3. **회사 양식 파일은 그 양식 그대로 둔다.** 회사 시스템에 올릴 파일일 수 있으므로 시트를 더하지 않는다. 검산 결과는 따로 `검산_번호.xlsx` 로, 출력 폴더가 아니라 그 작업 폴더의 `검산\` 에 둔다(5-1 의 「검산 시트」를 이것으로 바꿈). 「누적장부만」이면 문서별 결과 파일은 만들지 않고 검산 파일만 남긴다.
4. **중복 판정은 출력 방식과 관계없이 한다.** 「회사 양식만」이어도 작업마다 처리 기록(처리로그·내부 목록)으로 같은 번호 문서를 두 번 내보내지 않는다.
5. **검산의 반올림·부대비용**
   - 줄 검산: 수량 × 단가를 **금액의 소수 자리로 반올림**한 값이 금액과 같으면 통과(단가 소수가 길면 금액은 반올림된 값이 정상이므로). 반올림 방식은 사사오입·은행원식 둘 다 허용.
   - 합계 검산: 규칙에 「소계」 필드가 있으면 품목 합 = 소계. 「합계」와 부대비용 필드(운임·세금 등, 규칙에 이름으로 적음)가 있으면 소계 + 부대비용 = 합계. 규칙에 해당 필드가 없으면 그 검산은 「해당 없음」. 예시 Invoice(Subtotal · Freight · Total)가 이 방식으로 통과해야 한다.
   - 원문 대조와 소수 자리 검사는 반올림 없이 그대로.
   - 원본에 없는 값(줄번호 · 고객마스터 값 · 고정값 · 수량x단가 계산값)은 원문 대조에서 빼고, 계산값은 줄 검산으로 확인한다.
6. **한 작업이 여러 고객의 서로 다른 양식을 받을 수 있다.** 새 고객 양식은 Code 탭에서 「○○ 작업에 이 고객 양식 더해 줘」로 더한다(05장). **승인 수는 양식 단위**(문서 종류 · 엑셀양식 하나)로 센다. 새 양식을 더하거나 한 양식의 규칙을 고치면 **그 양식만** 0으로 되돌리고, 이미 검증된 다른 고객 양식은 그대로 둔다.

## 11. 남은 것 (설계자 몫)

- 작업지시서 시작 방법(슬래시 명령 vs 한 줄).
- 알림 방법(PC 안에서만).
- 누적장부 위치(작업 폴더 vs 출력 폴더).
- 원문 대조의 엑셀 값 처리 세부.

## 12. 추가 결정 (2026-10-28, 계획 뒤) — 위 절과 다르면 이 절이 이긴다

### 12-1. 입력 폴더의 원본은 옮기지 않는다 **[대표]**
- 처리한 원본을 `정리문서\` 로 옮기지 않는다. 입력 폴더는 친구의 폴더이고, 친구가 원할 때 직접 정리한다.
- 작업마다 `처리기록.csv`(작업 폴더)에 파일 지문(내용 sha256) · 파일 이름 · 문서종류 · 번호 · 상태(성공 · 중복 · 확인필요 · 승인대기) · 규칙 지문 · 처리 날짜를 남긴다.
- 다음 실행에서 지문이 이미 성공 · 중복 · 승인대기로 기록된 파일은 건너뛴다. 이름을 바꾸거나 같은 파일을 다시 넣어도 다시 처리하지 않는다.
- 확인필요로 기록된 파일은 같은 날에는 건너뛰고, **다음 날** 또는 **그 작업 규칙이 바뀐 뒤** 다시 시도한다 **[설계자 판단, 대표에게 이렇게 설명함]**.
- 내용이 다른 새 파일인데 (문서종류, 번호)가 이미 성공으로 기록돼 있으면 「중복」으로 기록하고 처리하지 않는다(알림에 포함).
- 판별이 안 된 파일은 기록하지 않는다(다른 작업 몫일 수 있음). 「어느 작업에도 맞지 않는 파일」 = 같은 입력 폴더를 쓰는 모든 작업의 처리기록 어디에도 없고 수정 시각이 24시간 넘은 파일.
- 확인필요: 작업 폴더 `확인필요\` 에 사유 `.txt` 만 둔다(원본 경로 · 사유). 원본은 복사하지 않는다.
- 승인대기: 원본의 **복사본**을 작업 폴더 `승인대기\` 에 두고(친구가 입력 폴더 원본을 지워도 승인 가능), 대조표는 `승인대기\대조표\`. 승인 처리 뒤 복사본은 지운다. 승인하지 않을 문서는 친구가 그 복사본을 지우면 된다(처리기록은 승인대기로 남아 다시 처리되지 않음. 다시 처리하려면 규칙을 고친다).
- 작업 폴더의 `정리문서\` 는 만들지 않는다.

### 12-2. 결과 알림 **[대표]**
- 실행(자동 · 지금 실행 · 승인)이 끝나고 새 결과가 1건 이상이거나 확인필요 · 중복 · 승인대기 · 어느 작업에도 맞지 않는 파일이 있으면 Windows 알림(화면 오른쪽 아래)을 띄운다. 예: 「일일 PO 정리: 결과 3건, 확인필요 1건」.
- 알림을 누르면 출력 폴더가 열린다(확인필요 · 승인대기만 있으면 작업 폴더).
- 새 파일이 없어 할 일이 없었으면 알림을 띄우지 않는다.
- 알림은 PC 안에서만 뜬다(PowerShell 의 Windows 알림 기능). 안 되면 메시지 창으로 대신한다 **[설계자 판단]**.

## 13. 추가 결정 (2026-10-28 밤) — 파트별 마크업 · 메일 본문 PO

### 13-1. 메일 본문으로 온 PO **[대표]**
- 친구가 Outlook 에서 인쇄 → 프린터에서 PDF 선택 → 그 작업의 입력 폴더에 저장한다. 프로그램은 다른 PDF 와 똑같이 처리한다(새 코드 없음). 글자 없는 PDF 는 기존대로 「텍스트 없음」 확인필요.

### 13-2. 파트별 마크업 **[대표]**
- 친구는 고객 PO 의 단가에 파트넘버마다 정해진 마크업(0~3% 등)을 붙여 **본사용 PO 시트(엑셀)**를 만든다. 예: A파트 3% → $0.10 × 1.03 = $0.103. 파트는 수백 개 이상.
- 마크업 목록은 작업 폴더의 `마크업표.xlsx`(작업 공용, 고객마스터처럼). 친구가 직접 고치고 Claude 는 열지 않는다. 첫 줄 머리글: `파트넘버` · `마크업%` (선택 `반올림자리`).
- 본사 단가 = 고객 단가 × (1 + 마크업% ÷ 100). 본사 금액 = 수량 × 본사 단가. **기본은 반올림하지 않는다 [대표: 소수점 규칙 모름 → 그대로]**. `반올림자리` 가 있는 파트만 그 자리에서 사사오입 **[설계자 판단]**.
- 마크업표에 없는 파트가 하나라도 있으면 그 문서는 확인필요(사유에 빠진 파트넘버 나열). 0% 로 넘기지 않는다 **[설계자 판단, 대표에게 설명함]**.
- 회사 양식(본사 PO 시트)의 열 값에 `마크업.단가` · `마크업.금액` · `마크업.율` 을 쓸 수 있다. 누적장부는 고객 PO 값 그대로 **[설계자 판단]**.
- 검산: 줄마다 본사 단가 = 고객 단가 × (1 + 율)(반올림자리 있으면 그 자리로), 본사 금액 = 수량 × 본사 단가, 마크업% 는 0 이상 10 이하(넘으면 확인필요) **[설계자 판단]**. 대조표 · 검산 파일에 줄마다 마크업% 와 본사 단가를 보여 준다.
- 마크업표가 바뀌면 같은 날이라도 확인필요 문서를 다시 시도한다(빠진 파트를 더한 뒤 바로 다시 실행할 수 있게). 승인 수(양식 지문)에는 넣지 않는다(데이터이므로) **[설계자 판단]**.
