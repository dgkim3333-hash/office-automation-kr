# 설치 없는 판(무설치판) 설계

작성 2026-10-29. 기존 설계(`2026-10-28-office-automation-kr-design.md`, `2026-10-28-work-orders-design.md`)는 그대로 두고, 그 옆에 대비책으로 하나를 더 만든다.
표기: **[대표]** = 대표가 대화에서 정한 것, **[설계자 판단]** = 이 문서를 쓴 쪽이 정한 것(대표가 읽으며 확인), **[시험판]** = 2026-10-29 버린 시험판으로 확인한 사실.

## 1. 왜

친구 회사 PC에는 지금 프로그램(uv · 파이썬 · 저장소 내려받기)을 설치하지 못할 수 있다 **[대표]**. 그 경우에 쓸 대비책이 필요하다.

- 처음에는 Claude Desktop 「예정됨」(로컬 예약 작업)으로 Claude 가 매일 PO 를 정리하는 안을 봤다 **[대표]**.
- 하지만 로컬 예정됨이어도 Claude 가 읽은 파일 내용은 Anthropic 서버로 간다(Claude Code 문서 desktop-scheduled-tasks · data-usage, 2026-10-29 조회). 친구 회사가 거래처 자료를 AI 에 넣어도 되는지 모른다 **[대표]**. 그래서 이 안은 쓰지 않는다.
- 대신 **친구 PC 에 이미 있는 Windows PowerShell 과 오피스(엑셀 · 워드)만으로** PC 안에서 처리한다 **[대표 승인]**.

[시험판] 이 PC(Office 16)에서 PowerShell + COM 으로 `C:\PO시험` 의 가짜 PO 3개를 읽었다.
- 엑셀 PO 1개: 9줄, 단가 4자리, 합계 473,324.06 이 정답표와 같다. 1.8초.
- PDF 2개(워드 PDF 변환): 7줄 · 5줄, 합계 356,028.15 · 744,818.26 이 정답과 같다. 2.4초 · 0.8초.
- 이 시험판 코드는 버린다. 새로 짠다.

## 2. 목표 · 하지 않을 것 · 실패로 보는 것

목표 (핵심만 **[대표]**)
1. 입력 폴더의 엑셀 PO(.xlsx)는 엑셀로, PDF PO 는 워드로 읽는다.
2. 검산한다(5절). 맞으면 출력 폴더에 **회사 양식 엑셀**을 만들고 **누적장부**에 더한다.
3. 안 맞거나 못 읽은 문서는 **확인필요**로 두고 이유를 남긴다.
4. 이미 처리한 파일은 다시 처리하지 않는다.
5. 바탕화면 「지금 실행」과 매일 자동 실행(가능하면)으로 돈다. 결과는 Windows 알림.
6. 친구 PC 에는 **아무것도 설치하지 않는다**. 폴더 하나를 복사해 넣고 처음 한 번 준비 스크립트를 돌리면 끝.

7. **파트별 마크업**은 넣는다 **[대표, 2026-10-29]**. 지금 판 work-orders 설계 13-2 와 `app\markup.py` 의 규칙을 그대로 따른다(4-4).

하지 않을 것 **[대표: 핵심만]**
- 승인 10건, 고객마스터, Outlook 자동 수집. 필요해지면 나중에 더한다.
- 친구 PC 에서 Claude 를 쓰는 것(예정됨 포함). 친구 PC 의 매일 처리에 AI 가 끼지 않는다.
- 인터넷 내려받기 · 관리자 권한 · 설치 프로그램(winget 등).
- 스캔(그림) PDF 글자 인식. 글자가 없는 PDF 는 확인필요.

실패로 보는 것 (돌아가더라도)
- 숫자 한 자리, 소수점 한 자리라도 원본과 다른 값이 회사 양식이나 누적장부에 **조용히** 들어감.
- 회사 문서 내용이 PC 밖으로 나감.
- 워드 · 엑셀이 숨은 확인 창에서 멈춰 그날 처리가 통째로 안 되는데 아무도 모름.
- 친구가 명령어를 쳐야 함.
- 친구 PC 의 시스템 · 보안 설정을 바꿈.

## 3. 전체 모습

```
대표 PC (지금 프로그램 + Claude + 오피스)          친구 PC (Windows + 오피스만)
 1. Claude 와 규칙.yaml 을 만든다(작업지시서)
 2. 규칙을 무설치판 규칙(JSON)으로 내보낸다
 3. 무설치판 점검으로 예시 파일을 확인한다  ──복사(USB·메일)──▶  4. 폴더를 넣고 준비.bat 1회
                                                                    5. 매일: 자동 실행 / 지금 실행
```

- 규칙을 만들고 고치는 일은 **대표 PC** 에서 한다 **[대표]**. 친구 PC 에는 Claude 가 필요 없다.
- 예시 파일: 친구가 실제 PO 원본을 **양식마다 1개** 대표에게 보낸다(메일 · USB) **[대표]**. 그 원본은 대표 PC 에서 규칙을 만들 때 Claude(Anthropic 서버)가 한 번 읽는다. 문서(무설치판 장)에 「원본 1개가 친구 회사 밖(대표)으로 나가고 Claude 에게도 한 번 간다. 보내기 전에 회사에 확인」을 그대로 적는다. 대표 PC 에서는 이 원본을 저장소 밖에 두고, 지울 때는 대표가 정한다 **[설계자 판단]**.
- 대표 PC 의 지금 판 작업 만들기(작업지시서)는 친구 PC 가 아니라 대표 PC 기준으로 쓰인다. 입력 · 출력 폴더는 대표 PC 의 시험용 폴더로 두고, 친구 PC 의 실제 폴더는 준비.bat 이 묻는다 **[설계자 판단]**.
- 규칙은 지금 판의 `규칙.yaml` 형식을 그대로 쓴다 **[대표]**. 단, 무설치판이 쓰지 않는 기능(4-2)이 들어 있으면 내보내기에서 거절한다.

## 4. 규칙

### 4-1. 내보내기 **[설계자 판단]**

Windows PowerShell 5.1 에는 YAML 읽기가 없고, 친구 PC 에 모듈을 설치할 수 없다. 그래서:
- 지금 프로그램에 명령 하나를 더한다: 작업 NN 의 `규칙.yaml` 을 읽어(지금 엔진의 검사를 그대로 거친 뒤) 무설치판이 읽는 `규칙.json` 으로 내보낸다. 이름은 설계자 판단(예: `export-portable NN`).
- JSON 에는 문서종류 · 엑셀양식 · 회사양식 · 시트순서를 지금 엔진이 해석한 그대로 담는다. 무설치판은 PowerShell 내장 `ConvertFrom-Json` 으로 읽는다.
- 이 명령은 대표 PC 에서만 쓴다. 출력은 작업 폴더 안(저장소 밖)에 둔다.

### 4-2. 무설치판이 지원하는 것

| 지원 | 거절(내보내기에서 오류) |
|---|---|
| 문서종류: 판별키워드 · 번호필드 · 필드(패턴, 형식: 날짜/금액) · 표(시작키워드 · 끝키워드 · 행패턴 · 열 · 금액열 · 수량열) · 검산(소계 · 부대비용 · 합계) | 회사양식 값 `고객마스터.*` |
| 엑셀양식: 문서종류 · 판별키워드 · 머리(셀 주소 · `오른쪽:글자` · 형식) · 품목(머리글 · 열 · 금액열 · 수량열) | 그 밖에 무설치판에 없는 규칙 항목 |
| 회사양식: 파일명 · 시트 · 열(머리.X · 품목.X · 줄번호 · 수량x단가 · 고정: · 빈칸 · 마크업.단가 · 마크업.금액 · 마크업.율) · 마크업 열 이름 바꾸기(품번열 · 단가열 · 수량열) | |
| 시트순서 | |

정규식: 지금 규칙은 Python 정규식이다. .NET 정규식과 대부분 같지만 다를 수 있다. 내보내기 때 패턴마다 .NET 에서도 컴파일되는지, 같은 시험 글자에서 같은 결과를 내는지 4-3 의 점검으로 확인한다. 차이가 나는 문법 목록과 처리는 설계자 몫.

### 4-3. 무설치판 점검 (규칙 확정의 관문) **[설계자 판단]**

워드가 PDF 에서 뽑는 글자는 지금 프로그램(pdfplumber)이 뽑는 글자와 다르다. [시험판]에서 본 차이:
- 열 사이가 탭 또는 여러 칸 띄어쓰기다.
- **줄 앞 번호(1, 2, 3 …)가 워드의 글머리 번호 목록이 되어 글자에서 빠진다.**
- 가로줄이 `/` 한 글자 줄로 나온다.
- 메일 인쇄 PDF 의 머리(From · Sent …)는 워드 표가 되고, 칸이 줄로 나뉜다.

그래서:
1. 무설치판은 워드 글자를 **정규화**한다. 목록 번호를 되살리고(각 문단의 목록 번호 글자), 탭 · 연속 띄어쓰기를 한 칸으로 줄이며, 가로줄 흔적을 지운다. 목표는 「pdfplumber 글자로 만든 규칙이 정규화한 워드 글자에도 그대로 맞는 것」. 정확한 정규화 방법은 설계자 몫이고, 4번 시험으로 확인한다.
2. 그래도 맞지 않는 PDF 가 있을 수 있으므로, **무설치판 자체에 점검 명령**을 둔다. 예시 파일 1개를 읽어 지금 판 `check` 와 같은 결과 표(항목 · 값 · 검산)를 보여 준다.
3. 대표 PC 에서 규칙을 확정할 때 지금 판 `check` 와 **무설치판 점검을 둘 다** 통과시킨다. 무설치판 점검을 통과하지 못한 규칙은 친구에게 넘기지 않는다.
4. 저장소 시험 자료(samples · tests 의 가짜 PDF)와 `C:\PO시험` 의 3개로 「두 판이 같은 결과를 낸다」를 시험한다(8절).

### 4-4. 마크업 **[대표: 넣는다 / 내용은 지금 판 그대로]**

- 친구 PC 작업 폴더 맨 위의 `마크업표.xlsx`(파트넘버 · 마크업% · 반올림자리)를 엑셀로 읽는다. 친구가 직접 채운다. 준비.bat 은 없을 때만 빈 예시(가짜 품번)를 만든다.
- 본사 단가 = 고객 단가 × (1 + 마크업% ÷ 100), 본사 금액 = 수량 × 본사 단가. 계산은 `[decimal]`.
- 읽는 법 · 거절하는 경우는 `app\markup.py` 와 같다: `3` = 3%, 1% 미만은 `0.5%` 처럼 % 기호나 백분율 서식, 반올림자리가 있을 때만 사사오입(ROUND_HALF_UP), 비면 반올림 안 함, 같은 파트 두 줄 · 잘못된 값은 오류, 파트넘버 비교는 앞뒤 공백 빼고 대소문자 무시(숫자 칸 12345.0 = 12345), 마크업% 상한 · 반올림자리 상한도 같은 값.
- **마크업표에 없는 파트가 하나라도 있으면 그 문서는 확인필요**(0% 로 넘기지 않음). 사유에 파트넘버를 적는다.
- 마크업표를 고치면 그날 확인필요였던 문서를 다음 실행 때 다시 시도한다(지금 판과 같음).
- 마크업표가 엑셀에 열려 있을 때의 동작도 지금 판과 같게 한다(지금 판은 파일 내용을 한 번 읽어 쓴다). 무설치판은 엑셀로 읽으므로 읽기 전용 복사본을 임시 폴더에 만들어 연다(6절 1과 같은 방식) **[설계자 판단]**.
- 매일 처리에서 Claude 는 마크업표를 열지 않는다(친구 PC 에는 Claude 가 없음). 대표 PC 에서 규칙을 만들 때도 Claude 는 친구의 마크업표를 열지 않는다(지금 판 CLAUDE.md 8항). 대표 PC 시험에는 가짜 마크업표를 쓴다.
- 「두 판 같은 결과」 시험에 마크업 열(본사 단가 · 본사 금액 · 마크업%)을 포함한다. `C:\PO시험\03_고객마스터_마크업\마크업표.xlsx` 와 저장소 시험의 가짜 마크업표를 쓴다.

## 5. 정확성 확인 (매번, 모든 문서)

지금 판 work-orders 설계 5-1 을 그대로 따른다. 하나라도 어긋나면 결과 · 장부에 넣지 않고 확인필요.
1. 원문 대조: 결과의 숫자 · 번호 · 날짜는 원본 글자에 있어야 한다. 엑셀은 셀에 저장된 값과 표시 형식 자리 수 기준(지금 판과 같은 방법).
2. 줄 검산: 수량 × 단가 = 금액(금액의 소수 자리로 반올림, 엑셀은 최소 2자리 — 지금 판과 같음).
3. 합계 검산: 품목 합 = 소계, 소계 + 부대비용 = 합계(부대비용이 문서에 없으면 0).
4. 소수 자리 수: 결과 값의 자리 수 = 원본 자리 수. 반올림 · 잘라내기 금지. 계산은 `[decimal]` 로 한다(부동소수 금지).
5. 저장 후 재읽기: 결과 엑셀 · 누적장부를 저장한 뒤 다시 열어 방금 쓴 값과 한 칸씩 대조.

문서마다 검산 기록(항목 · 원본 값 · 결과 값 · 일치)을 작업 폴더 `검산\` 에 남긴다.

## 6. 멈춤 · 확인 창 대비 [시험판 근거]

[시험판] 숨은 워드가 확인 창에서 멈춰 16분 넘게 기다린 일이 있었다. 원인은 두 가지였다.
- 「PDF 를 편집 가능한 Word 문서로 변환합니다」 안내. 레지스트리 `HKCU\Software\Microsoft\Office\16.0\Word\Options\DisableConvertPdfWarning` = 1 이면 뜨지 않는다(대표가 「다시 표시 안 함」을 체크해 확인).
- 「마지막으로 '파일'을 열었을 때 오류가 발생했습니다」. 워드가 비정상 종료되면 **그 파일 경로**를 기억했다가 묻는다. 새 이름의 임시 폴더에 복사본을 만들어 열면 뜨지 않았다.

대비 **[설계자 판단]**
1. PDF 는 언제나 실행마다 새로 만든 임시 폴더의 복사본을 연다(원본은 건드리지 않음). 엑셀 PO 도 같은 방식.
2. 파일 하나당 시간 제한(예: 120초, 설계자 몫). 넘으면 그 실행이 띄운 워드/엑셀만 끝내고, 그 문서를 「워드가 응답하지 않음」으로 확인필요에 보낸 뒤 다음 문서로 간다.
3. 끝낼 때는 **이 실행이 COM 으로 띄운 프로세스(명령줄 `/Automation -Embedding`)만** 끝낸다. 친구가 직접 연 워드 · 엑셀은 건드리지 않는다.
4. PDF 변환 안내: 준비.bat 이 친구에게 「워드에서 PDF 를 한 번 열고 '다시 표시 안 함'에 체크」를 안내하고, 실행할 때 값이 1 이 아니면 PDF 를 건너뛰고 알림으로 같은 안내를 한다. 프로그램이 이 설정을 직접 바꾸지 않는다(2절 실패: 친구 PC 설정을 바꿈).
5. Quit 뒤 프로세스가 실제로 사라질 때까지 기다린다([시험판] Quit 직후 남아 있던 일이 있었다).
6. 인터넷에서 받은 파일(메일 첨부)의 「보호된 보기」가 COM 열기를 막는지는 확인하지 않았다. 설계자가 Zone.Identifier 가 붙은 복사본으로 시험하고, 막히면 복사본에서 표시를 떼고 연다(원본은 그대로).

## 7. 실행 · 폴더 · 전달

- 대상: **Windows PowerShell 5.1**(Windows 기본). PowerShell 7 문법 금지. 스크립트는 한글 때문에 UTF-8(BOM) 으로 저장 **[설계자 판단]**.
- 실행은 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File …` 로 바로가기 · 예약 작업에서 부른다. 회사 그룹 정책이 스크립트 실행 자체를 막으면 이 판도 못 쓴다 → 99장 「IT 담당자에게 물어볼 문장」에 추가.
- 매일 실행: 지금 판 work-orders 6절의 「막히면 다음 방법」을 그대로 따른다(작업 스케줄러 → 시작프로그램 → 지금 실행만). 시각 규칙도 같다(16:00 + 20분 × (순번 − 1)).
- 같은 작업이 겹쳐 돌지 않게 잠근다. 저장한 지 1분이 안 된 파일은 다음 실행으로 미룬다(지금 판과 같음).
- 이미 처리함 판별: 파일 내용 해시(`Get-FileHash`)를 처리기록에 남긴다. 이름을 바꿔도 다시 처리하지 않는다. 입력 폴더의 원본은 옮기거나 지우지 않는다.
- 누적장부 · 회사 양식 · 처리로그의 모양은 **지금 판과 같게** 한다 **[설계자 판단]**. 나중에 친구 PC 에 지금 판을 설치할 수 있게 되면 같은 장부를 이어 쓸 수 있게 하려는 것. 같게 못 하는 부분은 설계자가 적어 둔다.
- 장부나 결과 파일이 엑셀에 열려 있으면 그 실행은 보류하고 알린다(지금 판과 같음).
- 알림: 지금 판 `notify.py` 와 같은 Windows 알림, 실패하면 메시지 창.
- 저장소 안 위치: `무설치판\` 폴더 **[설계자 판단]**. 친구에게는 이 폴더 + 작업별 `규칙.json` 을 묶어 넘긴다. 묶는 방법(대표 PC 에서 zip 을 만드는 명령 등)은 설계자 몫.
- 친구 PC 의 작업 폴더 구조: 지금 판과 같은 `작업\NN_제목\` (작업설정 · 규칙 · 처리기록 · 확인필요 · 검산 · 실행기록). 작업설정은 JSON.
- 준비.bat(처음 1회): 오피스 · PowerShell 버전 확인 → 입력 · 출력 폴더 고르기 창 → 작업 등록(매일 실행 방법 결정) → 바탕화면 「지금 실행 - 제목」 → 6절 4 안내. 친구는 두 번 클릭과 폴더 고르기만 한다.
- 로컬 디스크만: OneDrive · 네트워크 드라이브 · UNC 폴더는 거부(지금 판 원칙).
- 인터넷 연결을 쓰지 않는다. 스크립트 안에 내려받기 · 웹 호출이 없어야 한다(시험으로 확인).

## 8. 시험에서 꼭 다룰 것

- **두 판 같은 결과**: 저장소의 가짜 PDF · 엑셀 PO 와 `C:\PO시험` 3개에 대해 지금 판과 무설치판의 회사 양식 · 장부 값이 칸마다 같다. 무설치판 시험은 오피스가 있어야 하므로 표시를 붙여 오피스 없는 곳에서는 건너뛴다.
- 줄 번호가 목록 번호로 빠지는 PDF, 2쪽 PDF, 메일 인쇄 PDF.
- 자리 다른 숫자 · 소수점 다른 숫자 · 표기만 다른 같은 값 · 엑셀 부동소수(0.1 류).
- 줄 · 합계 검산 불일치 → 확인필요, 결과 · 장부 무변화.
- 워드가 응답하지 않을 때(시간 제한) → 그 문서만 확인필요, 다음 문서 계속, 사용자가 연 워드는 살아 있음.
- 「지난번 오류」 창: 같은 파일을 두 번째 실행에서도 연다(임시 복사본 방식 확인).
- 이미 처리한 파일(이름 바꿈 포함) 건너뜀, 1분 안 된 파일 미룸, 장부가 열려 있으면 보류.
- 내보내기: `고객마스터.*` 가 든 규칙은 거절, 지원 규칙(마크업 포함)은 JSON 으로 나와 무설치판이 같은 뜻으로 읽음.
- 마크업: 표에 없는 파트 → 확인필요, 같은 파트 두 줄 · 잘못된 % → 오류, 1% 미만 표기, 반올림자리 있음 · 없음, 마크업표를 고친 뒤 재시도.
- 저장소 규칙대로 전체 `uv run pytest` 녹색.

## 8-1. 검토 뒤 정한 것 [설계자 판단, 대표가 읽으며 확인]

1. **친구 PC 오피스가 다를 수 있다**: 워드 버전마다 PDF 글자가 다를 수 있다. 무설치판 묶음에 **가짜 시험 PO(저장소 samples 의 ACME 류)와 그 정답값**을 넣고, 준비.bat 이 친구 PC 에서 그것을 읽어 정답과 같은지 확인한다. 다르면 「이 PC 의 워드는 PDF 를 다르게 읽습니다」로 멈추고 PDF 작업은 켜지 않는다(엑셀 PO 작업은 따로 판단). 레지스트리의 오피스 버전 번호(16.0)는 고정하지 않고 실제 설치된 버전에서 찾는다.
2. **작업 더하기 · 규칙 바꾸기**: 대표가 새 묶음(작업별 규칙.json)을 보내면 친구는 묶음 폴더를 덮어쓰고 준비.bat 을 다시 두 번 클릭한다. 이미 등록된 작업은 폴더를 다시 묻지 않고 규칙만 바꾸며, 처리기록 · 장부는 그대로 둔다. 새 작업만 폴더를 묻는다. 규칙이 바뀐 작업의 확인필요 문서는 다음 실행 때 다시 시도한다(지금 판과 같이 규칙 지문으로 판단).
3. **`C:\PO시험` 시험 자료**: 대표가 직접 시험하려고 만든 가짜 자료다(실제 고객 자료 아님). 지금 판 규칙(`04_정답\참고_검증된_규칙.yaml`)과 정답표(`04_정답\정답표_기대결과.xlsx` · `누적장부_기대결과.xlsx`)가 이미 있다. 설계자가 열어 시험에 써도 된다. 단 저장소에는 복사하지 않고(저장소 CLAUDE.md: 저장소 안에 PDF · xlsx 를 만들지 않음), 이 자료를 쓰는 시험은 폴더가 없으면 건너뛴다. 저장소 안 시험은 저장소 samples · tests 의 가짜 자료로 한다.
